The latest Filza build centralizes pairing; its pairing-removal patches are intentionally not applied here. The standalone app restores a dedicated Device Pairing screen from the shared settings design, not a link into Filza.

The native Xcode app is built from the pinned upstream project with the extracted Filza patches and Swift compatibility modules in this directory. It keeps the original onboarding, music library, backup/repair, lyrics, album colors and custom Airlift/LocalDevVPN pairing. A manual pairing-file importer is restored alongside the iOS 27 on-device pairing host. Filza UI, file manager and wallet UI are not packaged. The upstream license is preserved; do not use this for media you do not have rights to.

Build: run the standalone workflow on this branch, or run prepare.sh from a fresh checkout on macOS with Xcode 26.2 and Rust and build the MusicManager scheme. The output is MP3-Skull-unsigned.ipa, bundle ID com.nightvibes33.mp3skull. The supplied icon artwork is installed in both native asset catalogs. Upstream attribution is retained. Minimum deployment target is iOS 17 (Airlift). On-device pairing specifically requires iOS 27; manual import remains available. Device pairing and library writes need real-device validation; CI compile is not such a test. The app uses a distinct bundle ID and no mandatory app-group entitlement.

## Pairing-only runtime

The standalone app compiles the pinned remote-pairing host and its vendored idevice FFI together, with a header generated by the same build. It does not stage NFCARD UI or compile Erosion's unrelated AirTraffic, wallet, app-container or filesystem modules. The full idevice feature set is retained for ABI compatibility. CI verifies required native symbols and rejects unrelated Airlift exports before building the app. Music transport continues through idevice and LocalDevVPN. Physical-device validation remains required.
