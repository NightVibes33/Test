# Zabbix High/Critical Audit

Target: zabbix/zabbix
HackerOne program: zabbix
Date: 2026-09-28

## Severity gate

Only pursue findings that meet the program's own rating guidance:

- Critical: significant compromise by an unauthenticated attacker.
- High: significant impact requiring ordinary user privileges.
- Discard administrator-only impact, speculative impact, and limited-impact findings.

## Current discarded paths

- Admin item-test SSRF / network access: program explicitly treats administrator SSRF as out of scope.
- Item-test execution controllers: require at least Zabbix Administrator, so they do not meet the High gate.
- OAuth token exchange controller: protected by Administration / Media Types permission.
- DPoP bypass of the normal API allow-list: current source intentionally exempts DPoP from the API list, including a 2026-09-14 fix that preserved this behavior; do not report without a distinct privilege boundary failure.
- Device onboarding: unauthenticated by design, but requires a 256-bit enrollment token generated by authenticated device.init and uses a transaction / FOR UPDATE before token consumption.

## Priority seams

1. Unauthenticated server/API/frontend parser paths leading to significant compromise.
2. Regular-user authorization bypass into admin-only state changes or code execution.
3. Fresh 2026 permission-model regressions, especially recent proxy / role changes, only if concrete High impact is proven.
4. Minimum PoC against an owned Zabbix instance/source build before any HackerOne submission.
